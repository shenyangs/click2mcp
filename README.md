# Click2MCP

“I clicked through a workflow once. It became an actual MCP tool.”

A local recorder-to-MCP bridge built with TypeScript, React, Vite, Express, Playwright Chromium, Zod 4 and the official MCP TypeScript SDK 2. The dashboard records real DOM events from a managed browser, validates a recipe, then discovers and calls `submit_demo_task` through an SDK stdio client. The tool runs the recipe in a fresh browser and returns the task receipt rendered by the bundled form.

## Run

Requires Node.js 22+ and npm. From this repository:

```sh
npm ci --cache .cache/npm
npm run browser:install
npm run dev
```

Open http://127.0.0.1:4208. The API is http://127.0.0.1:5208; both bind only to loopback. Keep these ports free. Browser downloads stay in `.cache/ms-playwright` within this repository. On Linux, Chromium also requires its normal OS libraries; the installer does not change system configuration. No parent or sibling project files are needed. An existing compatible macOS Playwright Chromium cache may be reused read-only if the local browser has not been installed.

## Three-step demo

1. Click **Start recording**, leave “Fix login issue” / “Engineering” selected, then click **Record form submission**. The dashboard controls send safe actions to the managed browser; the browser's DOM listeners capture `goto`, `fill`, `selectOption`, `click`. Expand the screenshot to see the actual fixture page and its first receipt.
2. Click **Generate MCP**. Inspect `submit_demo_task`, the argument schema, and the validated four-action JSON recipe.
3. Click **Test tool**. The SDK lists the registered tool, invokes it with the task name, and displays the new receipt from a fresh Chromium context. **Start recording** resets the workflow for another recording.

## What is real, and what is a fixture?

The website is explicitly a **bundled local fixture**. Browser automation, DOM event capture, SDK tool discovery, stdio invocation, submission and receipt generation are real. Receipts are generated by the fixture API with random IDs and held in memory. The dashboard shows the actual managed-browser screenshot, not a mock page image.

There is **no model inference** and no API key requirement. Recipe generation is deterministic validation/serialization, not AI code generation. An optional LLM description proposal is not implemented. `.env.example` documents this; no provider credentials are accepted or read.

```sh
npm run build
npm run test
npm run e2e
npm run demo
```

Verified locally: build passed, 9 unit tests passed, 3 end-to-end/integration tests passed, and the standalone recorded demo passed. `status.json` records the delivered checks. Test logs, a screenshot (`artifacts/demo.png`) and genuine Playwright WebM video (`artifacts/playwright/`) are generated locally and excluded from Git. `e2e` includes a real SDK listTools/callTool test and verifies the returned receipt through `/api/receipt/:id`; the UI demo makes the same assertion.

The first E2E attempt failed because the required FFmpeg revision was missing. Installing it in the project cache fixed that. A second attempt exceeded the default five-second UI assertion timeout while starting the subprocess/browser; the test now allows 20 seconds for observable results. Both failed logs are retained locally alongside the successful rerun. These are not reported as successful attempts.

## Scope and safety

- One local site, one generated generic tool, one in-memory recording session. This is a local development MVP, not a concurrent multi-user service.
- Exact origin, path, selectors, action types, category values and action sequence are allowlisted. Password fields, arbitrary selectors, scripts, shell commands, cross-origin requests and extra properties are rejected.
- The form supports only dummy task names up to 120 characters. Do not enter confidential text. Events and screenshots contain the dummy task text, so only use non-sensitive samples.
- The recorder is controlled through dashboard form controls; it is not a browser extension and does not capture an arbitrary desktop browser. Repeated submissions in one recording are rejected by recipe validation; start a fresh recording instead.
- Tool execution substitutes only `taskName`; category comes from the recorded recipe. Playwright actions time out after eight seconds, browser launch after 15 seconds. API JSON payloads are capped at 32 KiB; recordings at 16 events. The SDK uses its request timeout.
- The API rejects unapproved Origin and Host headers. This is not authentication: other local processes can use the API. Run only on a trusted workstation. Data and receipts disappear on restart; stop the dev server when done.
- No general website automation, durable recipe export/import, external MCP hosting, model integration, deployment or cross-platform runtime verification is claimed.
